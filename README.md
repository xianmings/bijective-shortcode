# bijective-shortcode

6 位短码生成的四种方案对比:自增、hash 截断、模幂双射、Feistel 网络。

结论先行 —— **双射置换把自增的"不重不漏"和 hash 的"杂乱无章"合到了一起**:
零碰撞由构造保证(不靠重试),输出不可枚举,而且可逆、无需额外维护映射表。
两种实现分别是模幂和 Feistel,区别只在置换怎么造。

```python
from shortcode import BijectiveScheme, FeistelScheme

scheme = BijectiveScheme()          # 也可换成 FeistelScheme()
code = scheme.encode(1)             # 例如 'L8Ezph'
scheme.decode(code)                 # 1
```

> 密钥每次构造都会重新随机生成,所以短码值本身不可复现。生产环境要把密钥
> 持久化,否则所有历史短码都会失效 —— 见[使用边界](#使用边界)。

---

## 问题

短链服务要把自增 ID 映射成定长短码。6 位 base62 的容量是 `62^6 = 56,800,235,584`,
约 568 亿 —— 存储层面非常宽裕,难点不在容量,而在**怎么映射**。

## 方案一:自增

```python
code = base62(identifier)
```

| 优点 | 缺点 |
|------|------|
| 零碰撞,天然一一对应 | **可枚举**:从 `oooooo` 试到 `jjjjjj` 就能爬完全站 |
| 容量 100% 利用,码最短 | **暴露业务量**:两个短码相减直接读出记录数差 |
| B+ 树顺序插入,写入局部性好 | **可预测**:能推算未生成的码,甚至预占 |
| 不需要任何额外存储 | 短码可直接换算回 ID,ID 又常被内部系统引用 |

可枚举这条是致命的。抓到一个短码,把它 +1 就是下一条记录的短码;
抓到年初和年末各一个,相减就知道这一年的业务量。

## 方案二:hash 截断

```python
code = base62(hash(identifier) % 62**6)
```

| 优点 | 缺点 |
|------|------|
| 不可枚举,输出无规律 | **碰撞无法消除**,只能靠额外存表 + 检测 + 重试 |
| 同一输入稳定复现 | **不可逆**,还原必须查 `code -> url` 表 |
| 实现简单,无状态 | 重试会破坏"同一 URL 同一短码"的天然去重 |

关键在于:hash 是**射入**(into)而非**射到**(onto)。它是多对一的,
碰撞不是实现缺陷,是数学后果 —— 换更长的摘要只是把碰撞概率推低,推不到零。

实测:

| 短码长度 | 码空间 | 投喂 ID 数 | hash 碰撞数 | 生日碰撞理论值 |
|---------|--------|-----------|------------|--------------|
| 4 位 | 14,776,336 | 200,000 | 1,387 | ~1,353 |
| 6 位 | 56,800,235,584 | 1,000,000 | 8 | ~8.8 |

理论值按 `n² / 2M` 估算(n 为投喂量,M 为码空间),与实测吻合。

6 位码下每百万条撞 8 次听起来不多,但短链是长期累积的:到了 1 亿条,
期望碰撞数涨到约 8.8 万次,每一次都要靠存表和重试去救。

## 方案三:模幂双射

```python
y = x^E mod N        # 生成:x 是自增 ID,y 是短码数值
x = y^D mod N        # 还原:D = E^-1 mod λ(N)
```

其中 `N = p * q`(p、q 为素数),`λ(N) = lcm(p-1, q-1)`。

### 为什么零碰撞

对 `N = p * q`(p、q 为不同素数),由中国剩余定理 `Z_N ≅ Z_p × Z_q`,
映射 `x → x^E mod N` 在两个分量上独立作用。

在 `Z_p` 上:`Z_p*` 是阶为 `p-1` 的循环群,`x → x^E` 在其上是双射
**当且仅当** `gcd(E, p-1) = 1`(又 `0 → 0` 固定,不影响)。对 q 同理。

于是 `x → x^E mod N` 是 `[0, N)` 上的双射,当且仅当

```
gcd(E, p-1) = 1  且  gcd(E, q-1) = 1   ⟺   gcd(E, λ(N)) = 1
```

**每个输入恰好对应一个输出,不重不漏。** 这是定理,不是概率 —— 所以不需要
碰撞检测,也不需要重试。逆元 `D = E^-1 mod λ(N)` 给出还原:
`(x^E)^D = x^(ED) ≡ x (mod N)`。

代码里用 `EXHAUSTIVE_LENGTH = 3` 的容量穷举了全部 238,328 个输入来验证这个
性质,而不是抽样。

### 为什么看起来随机

模幂高度非线性。输入 +1,输出在整个 `[0, N)` 上无规律跳变 —— 相邻 ID 的短码
数值差通常在数十亿量级:

| ID 对 | 自增方案差值 | 模幂双射差值 |
|-------|------------|-------------|
| 1000 → 1001 | **1** | 7,863,400,891 |
| 1000 → 2000 | **1,000**(直接泄漏记录数) | 7,850,206,056 |

## 方案四:Feistel 网络

目标与模幂完全相同,换一种构造。

### 一轮就一行

```
(L, R)  →  (R,  L ⊕ F(R, K))
```

把数据劈成左右两半:新的左半取旧的右半,新的右半取"旧左半异或 `F(旧右半, 轮密钥)`"。

**妙处在于 `F` 不需要可逆。** 反推一遍就看出来了:

```
(L', R') = (R, L ⊕ F(R, K))
R = L'                  ← 新的左半就是旧的右半
L = R' ⊕ F(L', K)       ← 用刚还原的 R 算出 F,再异或回去
```

所以 `F` 可以是查表、可以是 hash、可以完全不可逆 —— 每一轮都必然是置换。
本实现用带密钥的 BLAKE2b 当 `F`,刻意选不可逆的构造,就是为了体现这一点。

### cycle walking:把置换收窄到任意区间

Feistel 是按位劈半的,所以它天然只能作用在 2 的幂大小的空间上。要让它的作用域
正好是 `62^6` 这种数,办法是:先在 `2^36 = 68,719,476,736` 这个更大的空间上跑
Feistel,**结果落在 `[0, 62^6)` 就采用,落在外面就再跑一轮**。

因为 `62^6 / 2^36 ≈ 0.827`,平均 **1.21 次**就出结果,即平均多跑 0.21 遍。
这个反复重算直到落进目标区间的手法就叫 cycle walking,它的输出仍然是一个置换,
所以零碰撞的性质不受影响。

### 为什么轮数不能少

Luby-Rackoff 定理:3 轮 Feistel 在伪随机函数假设下已经是伪随机置换(能抵抗
选择明文),4 轮更强(抵抗选择密文)。轮数不够时它**仍然是个合法置换** ——
功能测试查不出问题,但输出和随机置换可区分。本实现在构造期就拒绝 `rounds < 3`,
把这类缺陷挡在编译期而不是线上。

## 四种方案横向对比

| 维度 | 自增 | hash 截断 | 模幂双射 | Feistel |
|------|------|----------|---------|---------|
| 碰撞 | 无 | 有,需重试 | **无(数学保证)** | **无(数学保证)** |
| 可枚举 | 是 | 否 | **否** | **否** |
| 可逆 | 是 | 否 | **是** | **是** |
| 需额外存表 | 否 | 是 | **否** | **否** |
| 容量利用率 | 100% | <100% | 99.997% | **100%** |
| 还原方式 | 减 | — | 一次模幂 | 倒跑一轮 |
| 顺序写入局部性 | 优 | 差 | 差 | 差 |
| 生成速度 | 117 万/秒 | 57 万/秒 | 41 万/秒 | 15 万/秒 |

速度来自 `demo.py`,本机单线程实测。两个双射方案都慢于自增和 hash,
Feistel 又比模幂慢一倍多 —— 主要开销在每轮一次 BLAKE2b,平均一次编码要跑
约 4.8 次。这个量级对短链场景够用:短码只在创建时生成一次,后续命中走缓存。

### 模幂 vs Feistel,选哪个

| | 模幂 | Feistel |
|---|------|---------|
| 容量利用率 | 99.997%(模数必须是两素数之积) | **100%**(按位宽工作,不受限) |
| 还原 | `x = y^D mod N`,一步到位 | 每一轮倒着跑一遍,无闭式解 |
| 速度 | 41 万/秒 | 15 万/秒 |
| 密钥 | 两个素数 + 指数 | 一个字节串 |
| 安全性依据 | RSA 的代数结构 | Luby-Rackoff 定理 |

要容量吃满、能接受还原多跑一遍,选 Feistel;要还原一步到位、能接受极小浪费,选模幂。

## 使用边界

这一节比上面重要 —— 用之前必须知道它做不到什么。

**它不是密码学强度,而且天花板是短码长度本身。** `N` 只有 36 比特,是为了塞进
6 位短码才刻意选小的;Feistel 的块宽同样只有 36 位。**短码只有 36 比特的取值空间,
任何构造都不可能给出超过 36 比特的安全性** —— 换更复杂的算法也没用,唯一的出路是
加长短码。所以:

- 它抗的是**枚举推断**(看到短码猜不出下一个、猜不出总量),不是**暴力破解**
- 模幂方案的 `p`、`q` 一旦泄漏,整个码空间可被枚举;分解 36 比特的数只需试除到
  `sqrt(N) ≈ 238,000`,毫秒级
- 要真正抗攻击,得先加长短码,再用经过审查的保格式加密实现(见[延伸](#延伸))

**密钥必须持久化。** 换密钥等于让所有历史短码失效。两套方案的密钥(模幂的
`(N, D)`、Feistel 的 key 字节串)都要当配置存起来,不能在每次启动时随机生成。

**写入没有局部性。** 短码列做唯一索引时,插入是随机分布的,B+ 树页分裂比自增
方案多。规避办法是别把短码当主键 —— 内部仍用自增 ID 做主键,短码只做外部标识。

**有不动点。** 模幂方案里满足 `x^E mod N == x` 的 x 会映射到自己,其中 `x=0` 和
`x=1`(`1^E` 恒为 1)会让前两个 ID 得到 `oooooo` 这种退化短码。两个方案都默认带
一个偏移把输入推离这些值,偏移量本身不参与运算。

## 延伸

上面两个方案都属于**保格式加密**(Format-Preserving Encryption)。同一个问题域下
还有别的做法,各自取舍不同。

### 什么是保格式加密

普通加密(AES 之类)不保证输出格式:给它 8 位数字,它吐回来一个定长的乱码块,
长度和字符集都不受你控制。

但短码场景的要求是硬性的 —— **输入是 ID,输出必须正好 6 个字符、只能从 62 个
字符里挑**。加密前后格式一模一样,这就是 FPE。本项目的两个方案都是 FPE 的朴素
实现:把 `[0, N)` 一一映射回 `[0, N)`,格式自动不变。

### Knuth 乘法散列:快,但是线性的

```
f(x) = (x * a) mod 2^k        a 取奇数
```

挑一个大奇数 `a`,把 ID 乘上它,只留结果的**后 k 位**(`mod 2^k` 就是取后 k 位)。

**为什么 `a` 必须是奇数**:偶数的话乘积永远是偶数,一半的输出永远取不到,
就不是双射了。奇数 `a` 与 `2^k` 互素,乘法在模 `2^k` 下可逆 → 双射成立。

**为什么比模幂快**:模幂用快速幂要做几十次乘法,这里只做**一次**。

**但它是线性的,这是致命弱点:**

- `f(x+1) - f(x) = a`,永远是这个常数 —— 相邻 ID 的码构成等差数列
- 因为 `a` 是奇数,乘积的最低位和原数最低位**完全相同**:
  短码的最后一个字符直接暴露 ID 的奇偶性
- 拿到两组已知的 `(ID, 短码)` 就能反解出 `a`,然后预测所有码

所以它那个"不规则"是**假的** —— 只有高位看着乱,算术结构还在。这跟模幂、
Feistel 是本质区别:后两者的乱来自非线性运算(指数、S 盒式轮函数),
乘法散列的乱只是"看起来"。

### Feistel 为什么是 FPE 的主流

因为它是唯一能做到**作用域任意**的构造:通过 cycle walking,可以对任意大小的
区间构造置换,不必迁就"必须恰好是 2 的幂"或"必须是两素数之积"。加上轮函数可以
随便换(不需要可逆),实现自由度很大。

NIST 在 SP 800-38G 里标准化的两种 FPE 模式 FF1 和 FF3-1 都是 Feistel 结构 ——
需要生产级实现时应该直接用它们,而不是本项目这种教学版本。

### Hashids:混淆,不是有证明的双射

一个现成的库,很多短链项目在用。思路是加盐 + 打乱字母表 + 一串"抽签字符"。但:

- **输出长度可变**(要支持一次编码多个数字,需要分隔符)→ 塞不进固定 6 位
- **作者在文档里明说它不是为安全设计的**
- 属于**混淆**而非**有证明的双射** —— 不可预测性全靠盐保密,没有任何定理撑腰,
  而且已经被学术界分析过

### 三条路线的取舍

| 做法 | 速度 | 非线性 | 作用域 | 还原 |
|------|------|--------|--------|------|
| Knuth 乘法散列 | 最快(一次乘法) | **否** | 2 的幂 | 求一次模逆 |
| 模幂(本项目) | 中 | 是 | 必须是两素数之积 | 闭式解,一步到位 |
| Feistel(本项目) | 慢(每轮一次 F) | 是 | **任意**(cycle walking) | 倒跑各轮 |

模幂这条路的独特价值在于**逆元有闭式解** —— `x = y^D mod N` 一步到位,
不需要跑反向网络。代价是模数必须由两个素数乘出来,作用域受限、容量用不满。

## 项目结构

```
shortcode/
├── base62.py        打乱字母表的 base62 编解码,定长输出
├── permutation.py   模幂双射:密钥生成、双射判定、双向映射
├── feistel.py       Feistel 网络:轮函数、轮密钥、cycle walking
└── schemes.py       四种方案的统一封装,便于横向对比
demo.py              四种方案的实测对比(形态/碰撞/可猜测性/可逆性/性能)
tests/               33 个测试,含双射性质的全量穷举验证
```

```bash
python demo.py                    # 对比演示

```
